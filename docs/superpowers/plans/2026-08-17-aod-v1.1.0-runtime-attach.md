# Lunaa Adaptive AOD v1.1.0 Runtime Attachment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the broken Context/constructor attachment in v1.0.x with one verified `transitionTo()` runtime-field attachment path for the exact July 5, 2026 crDroid 12.11 `lunaa` SystemUI build.

**Architecture:** `SystemUiHooks` creates one controller per live `DozeScreenBrightness` instance only from `transitionTo()`. It reads `mSensorManager`, `mDisplayManager`, and `mHandler` from the hooked instance, validates their runtime types, and passes them directly to a Context-free `AdaptiveAodController`; `resetBrightnessToDefault()` may only reapply an already-created controller.

**Tech Stack:** Java 17 production source, Android 16 / compileSdk 36, legacy Xposed API via compile-only local stubs, JUnit 4 source tests, PowerShell Windows build script.

## Global Constraints

- Target ROM: crDroid 12.11 / Android 16 / `lunaa`, build dated July 5, 2026.
- Hook scope remains only `com.android.systemui`.
- Do not hook System Framework / `android`.
- Remove `XposedBridge.hookAllConstructors(...)` completely.
- Remove all `mContext` reads and constructor-argument Context scanning completely.
- Do not add `ActivityThread.currentApplication()` or any alternate Context fallback.
- Controller creation may happen only from `transitionTo()`.
- `resetBrightnessToDefault()` must never create a controller.
- Keep existing brightness curve, hysteresis/debounce, sensor policy, fallback target, and UDFPS behavior unchanged.
- Fail open: missing/null/wrong-type dependencies leave stock behavior active and emit bounded Vector-visible diagnostics.
- Release version: `1.1.0`; source package and APK names must contain `v1.1.0`.
