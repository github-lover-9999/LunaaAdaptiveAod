# Lunaa Adaptive AOD v1.3.1 UI/UX Design

## Goal
Make the settings screen understandable at a glance, preserve all v1.3 runtime behavior, make Bright meaningfully bright by default, and fix Android 15/16 edge-to-edge/touch issues.

## Research-derived principles
- Do not copy references literally; reuse interaction patterns.
- Primary mode selection must be unmistakable and mutually exclusive.
- Main screen should expose the common path; expert controls belong behind an Advanced disclosure.
- Sliders need clear current meaning, not implementation jargon.
- Bottom actions and top content must respect system bar insets.
- Every interactive target must occupy at least 48dp x 48dp.

## Information architecture
1. Header: Lunaa Adaptive AOD + one-line description.
2. Module card: master switch and saved/apply status.
3. Mode selector: `Automatic` / `Manual` as the primary segmented control.
4. Mode-specific live card.
5. Automatic content:
   - Preset selector as the main control: Dim / Balanced / Bright.
   - One-line explanation that presets define how AOD responds to ambient light.
   - Live ambient lux + calculated AOD target.
   - `Advanced settings` collapsed by default.
   - Advanced contains Brightness adjustment, minimum brightness, and custom curve.
6. Manual content:
   - Fixed brightness as a percentage-first control.
   - Slider and exact normalized value.
   - No automatic preset/curve controls visible.
7. Sticky action bar: Reset and Save, padded above navigation/gesture/IME insets.

## Automatic semantics
Preset controls the shape/base values of automatic brightness. Brightness adjustment is only a fine-tune multiplier and is hidden in Advanced.

The multiplier backend remains 50-300% for compatibility. UI displays it relative to Normal:
- 50% backend => `-50%`
- 100% => `Normal`
- 150% => `+50%`
- 300% => `+200%`

## Preset calibration
Use brighter defaults so Balanced is a useful everyday profile and Bright is visibly bright without requiring a multiplier.

Lux points remain: `0, 2, 10, 50, 200, 500, 1000, 5000, 20000`.

Dim: `0.025, 0.030, 0.045, 0.080, 0.130, 0.190, 0.260, 0.400, 0.520`.
Balanced: `0.035, 0.045, 0.070, 0.130, 0.210, 0.300, 0.400, 0.580, 0.720`.
Bright: `0.050, 0.065, 0.100, 0.190, 0.300, 0.420, 0.540, 0.720, 0.850`.

## Android system UI behavior
The app targets SDK 36. Use edge-to-edge safely on API 30+ and consume `WindowInsets`:
- top scroll content gets system bar/display-cutout top inset;
- bottom sticky actions get the maximum of navigation/system-bar and IME bottom inset;
- horizontal content/action padding also accounts for side insets;
- interactive content never sits underneath system bars or gesture areas.

For API 26-29, retain conventional fitted system bars.

## Visual system
AMOLED-first, low-noise utility UI. Background `#070809`; surfaces `#131517`; elevated controls `#1C1F22`; warm amber accent `#FFC449`; high contrast text; 18-20dp cards. No gradients/glass/decorative imagery. Platform type only.

Selected states use accent fill or accent border. Unselected states use elevated dark surfaces. Preset cards include a short subtitle so intent is clear: `Dim · Night`, `Balanced · Everyday`, `Bright · Daylight`.

## Interaction/accessibility
- All buttons, segmented options, disclosure rows, switches and tap rows: >=48dp touch target.
- Advanced disclosure row is a full-width 48dp tappable row, not a tiny chevron.
- Save remains a high-emphasis action.
- Manual brightness shows both user-friendly percentage and exact normalized value.
- Curve edits change detected preset to Custom.
