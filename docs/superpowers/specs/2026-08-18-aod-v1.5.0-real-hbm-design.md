# Lunaa Adaptive AOD v1.5.0 — real AOD-HBM design

## Device evidence

On `AMS643YE01`, a store to `/sys/kernel/oplus_display/notify_fppress` only triggers the real AOD-HBM command when the logical value changes. Device validation proved that a forced `0 -> 1` edge produces `qcom,mdss-dsi-aod-hbm-on-command` and the same physical brightness class as the optical UDFPS phase.

A bare `notify_fppress=0` does not reliably emit the physical HBM-off command after a module-created edge because it does not own the DRM CRTC fingerprint-mode state. Therefore v1.5.0 never removes its protective dim layer while module HBM is latched inside an AOD session. Stock display exit remains authoritative for physical HBM-off.

## Behavior

- Manual 0–99%: normal Android doze brightness.
- Manual exactly 100%: request Extra Bright for the AOD session.
- Automatic: only Bright cap >=90%, >=7000 lux for 1.5 s.
- Extra Bright level: 80–100%, default 86%.
- HBM entry waits 5 s from ambient entry so the stock UDFPS startup cycle finishes first.
- Before HBM entry, attach a full-screen non-touchable black SystemUI layer.
- Convert requested level to black alpha as `(100 - percent) / 100`.
- Then write `notify_fppress=0`, wait 100 ms, write `1`.
- No periodic same-state reassert.
- Once HBM is latched, keep HBM + dim layer until AOD exits.
- On ambient exit, restore logical FP=0 and remove the dim layer after the stock display transition owns physical panel restoration.

## Failure safety

If the dim layer cannot be attached, do not issue the HBM edge. If the HBM edge fails after the dim layer is attached, remove the layer and retain normal AOD. No generic `/hbm`, DSI debug, panel register, kernel, vendor or ROM modification is used.
